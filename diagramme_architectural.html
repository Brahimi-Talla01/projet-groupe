3Couche Services Métier (Microservices avec DDD)

📚 Service Matières & Programmes

Gestion des matières par filière (C, TI, F4) et système (Fr/En) avec architecture en couches DDD

Architecture en couches (DDD)

Justification :

  • Règles métier complexes (coefficients, échelles de notes)
  • Modularité pour évolutions futures (nouvelles filières)
  • Séparation des responsabilités
  • Support offline via SQLite

Couches :

  • Présentation: Contrôleurs REST (GET /subjects/list, POST /subjects/create)
  • Application: SubjectApplicationService, CreateSubjectUseCase
  • Domaine: SubjectAggregate, Entities (Subject, Filiere), Value Objects (NoteScale), Domain Service (CoefficientCalculator)
  • Infrastructure: PostgreSQL (SubjectRepository), SQLite (OfflineSubjectRepository)

🧮 Service Notes & Bulletins

Cœur de la V1: saisie, calcul, validation et génération PDF avec architecture en couches DDD

Architecture en couches (DDD)

Justification :

  • Logique métier critique (calcul de moyennes, validation)
  • Événements de domaine pour notifications
  • Scalabilité pour pics de saisie
  • Génération PDF robuste

Couches :

  • Présentation: Contrôleurs REST (POST /grades/submit, POST /bulletins/generate)
  • Application: BulletinApplicationService, GradeValidationUseCase
  • Domaine: BulletinAggregate, Entities (Bulletin, Grade), Value Objects (Moyenne, Rang), Domain Event (BulletinValidatedEvent)
  • Infrastructure: PostgreSQL (BulletinRepository), PDF Generator (PdfBulletinGenerator)

⚖️ Avantages & Inconvénients

Analyse de l’architecture microservices avec couches DDD pour ces services

Architecture Microservices + DDD

Avantages :

  • Encapsulation des règles métier (ex. calcul de moyenne dans BulletinAggregate)
  • Séparation claire pour maintenance et tests
  • Scalabilité indépendante des services
  • Flexibilité pour personnalisation (ex. coefficients)
  • Résilience (panne d’un service n’affecte pas l’autre)

Inconvénients :

  • Complexité de gestion des couches et inter-services
  • Coût d’infrastructure (DBs, conteneurs)
  • Dépendances (ex. Notes dépend de Matières)
  • Latence potentielle via API Gateway
  • Tests d’intégration complexes
